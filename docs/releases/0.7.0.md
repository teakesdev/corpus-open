# Corpus Open 0.7.0

**Status:** prepared, not published. No tag or GitHub release exists yet.

This is the first tagged version of Corpus Open. Until now Hermes installed whatever `main`
held. The full list is in [CHANGELOG.md](../../CHANGELOG.md#070-unreleased).

## What is new

- **A case timeline.** Give a fact a date and the quote its source holds, and
  `matter_timeline` lists the case's facts oldest first. Each quote is checked against the
  registered document every time the timeline is shown, text files are cited by line, and when
  two sources give different dates for the same event, both are listed as a conflict. Nothing
  picks a side for you. New tools: `matter_fact_date` and `matter_timeline`.
- **City code cites are checked.** The citation guard now checks a cite such as
  `Austin City Code § 25-2-551` against the city's code in Corpus, when the cite names the city
  or you set the case's city with `/matter city TX-AUSTIN`.
- **A case-law research log.** `matter.py research` and six MCP tools record what you searched,
  where, and what is still to check.
- **The case-law coverage dataset is on `main`.** `matterkit/data/caselaw_coverage.json` says
  which courts' opinions CourtListener and the Caselaw Access Project hold, and for which years.

## What leaves your computer

One thing is new: a city code cite goes to Corpus (corpuslaw.us) with the city's Corpus code,
only when the cite or the case names the city. It is one more cite check, logged in
`.matter/egress.jsonl` like the others, and it is turned off with the other statute and code
checks, under the same grant. Nothing else changed: no reply text, facts, file names or documents are sent.

## Upgrading

Install again with `hermes plugins install teakesdev/corpus-open --enable`. Existing case
folders keep working: a case store gains the two timeline tables the next time it is opened, and
nothing already stored is rewritten. Facts recorded before this version have no date, so they
appear under "undated" on the timeline until you give them one.
