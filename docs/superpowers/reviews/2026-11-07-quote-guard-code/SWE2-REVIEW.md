# SWE-2 review — Hermes quote guard (`090bdf8..5dfa555`)

**Verdict: REQUEST CHANGES** — the architecture is right (reuse of `briefcheck._Checker` gives guard/`/matter check` agreement per D4; verdict mapping is complete; the hook cannot raise), but I found two deterministic bypasses of the blocking verdicts in the guard's core paths: a replace-mode patch that edits only a cite escapes checking entirely (P1-1), and patch-mode dispatch/V4A header parsing diverge from Hermes so real writes can go unchecked (P1-2). Both contradict D2's "not found and wrong page block the write" for routine agent input. The fixes are small and contained; details below. Method note: I worked read-only from `review.diff` plus the on-disk files at `5dfa555` (they match the diff), reading Hermes's `tools/file_tools.py` and `tools/file_operations*.py` for patch semantics as the handoff allowed; one stray read-only `ls` slipped in before I settled into read/grep/glob — no other commands were run.

## Findings

**P1-1 — `only` filters by substring-of-`new`, so a patch that edits only the cite is never checked.** `matterkit/quotecheck.py:87-89` (`(r.quote or r.cite) in o`), fed by `hermes_plugin/quote_guard.py:71-72` (`yield path.strip(), after, [new]`). For a quote-bearing result the filter tests only `r.quote`; the cite is never consulted. Any patch whose `new_string` doesn't restate the quoted words is invisible to the guard:

- Draft holds `He "never saw the warrant" Doc. 16 at 2.` (correct). `patch(old_string="at 2", new_string="at 1")` → post-edit text has the wrong-page result `("never saw the warrant", cite "Doc. 16 at 1")`, but `"never saw the warrant" in "at 1"` is False → filtered → write lands. Same for `replace_all=true` mass cite rewrites, doc-number retargets (`"Doc. 16"` → `"Doc. 18"` — even when the quote is in no page of Doc. 18 → not-found dropped), adding `at N` to a bare `Doc. 16`, and `Id.` → `Doc. N` rewrites.
- Bare page cites have the same hole: `patch(old="at 2", new="at 9")` on `See Doc. 16 at 2.` → `pin-out-of-range` result (`quote=""`, `cite="Doc. 16 at 9"`) is dropped because `"Doc. 16 at 9" in "at 9"` is False → write lands.

So the two blocking verdicts both escape precisely when the edit is a citation correction — a common patch shape and the exact class the feature exists to stop. Fix direction: attribute results to the replaced region, not to substrings of `new` — compute the replaced span's position in `after` (the `current.find(old)` offset), expand it to the enclosing unit/sentence, and keep results whose unit intersects it (`Result.line` alone is the unit's *start* line, so a cite-only edit on a folded citation-only line needs the unit's span, not just `line`). Testing `r.cite in o` too is a partial patch only — it still misses minimal edits like `new="at 9"`. A run-the-checker-on-`current`-too diff approach (keep results that are new or worsened) also works but doubles the per-write cost.

**P1-2 — patch-mode dispatch and V4A header parsing diverge from Hermes, leaving real writes unchecked.** `hermes_plugin/quote_guard.py:29, 56-64`.

- `mode` is ignored: `_writes` takes the V4A branch whenever `args["patch"]` is a non-blank string, but Hermes uses the `patch` arg only when `mode == "patch"` (`file_tools.py:971, 1005-1009`; `mode` defaults to `"replace"`). `patch(path="Drafts/x.md", old_string=…, new_string='He "forged it." Doc. 16 at 2.', patch="*** Update File: other.md …")` — Hermes patches `x.md` with the bad quote; the guard checks only `other.md`'s added lines (or nothing if the string has no headers) → pass. The mirror-image call (`mode="patch"` plus `path`/`new_string`) is consistent because Hermes also ignores the replace args then, but `mode="patch"` with a blank `patch` makes Hermes error while the guard may check text that is never written — spurious block of an erroring call, harmless but wrong.
- `_V4A_SECTION` (`^\*\*\* (?:Update|Add) File:`) is stricter than Hermes's parser. `_V4A_SINGLE_HEADER_RE` (`file_tools.py:150`, `\*\*\*\s*(Update|Add|Delete)\s+File:\s*`) accepts `***Update File:`, `***  Update  File:` and `***\tUpdate File:` — the file_tools comment says `***Update File:` "applies, so it must be checked". A model emitting any of those gets the patch applied while `finditer` yields zero sections → `_writes` returns → nothing is checked → the whole patch bypasses the guard.

Fix: read `mode` and branch exactly as `patch_tool` does; loosen the header regex to `^\*\*\*\s*(?:Update|Add)\s+File:[ \t]*(.+?)[ \t]*$` (Hermes also scans `Delete File:` and `Move File: a -> b` headers — worth matching the same set so future header forms can't drift).

**P2-1 — the in-memory replace simulation is exact-match UTF-8 only; Hermes's `patch_replace` is fuzzier.** `hermes_plugin/quote_guard.py:68-74` (`old in current`, `str.replace`), `_read` at `:77-87` (`errors="replace"`, no BOM strip, no line-ending normalization). `patch_replace` decodes surrogateescape, strips BOM, runs `fuzzy_find_and_replace` with correction strategies, and normalizes line endings in the substituted region (`file_operations.py:1636-1653`); it also reads UTF-16 files. Whenever `old in current` fails but Hermes still applies — a CRLF draft (agents send bare-LF `old_string`), a UTF-16 draft, or a whitespace-off `old_string` that fuzzy still lands — the guard falls to `yield path.strip(), new, None` and checks `new` context-free: a replacement that injects a bad quote into a sentence whose cite lives outside `new_string` reads as uncited → can't check → pass. Scenario: CRLF draft, `patch(old="<exact-old-that-fails-on-CRLF>", new='"burned the warrant"')` inside `… QUOTE. Doc. 16 at 2.` → draft ends with `"burned the warrant" Doc. 16 at 2.` unchecked. On CRLF files this hits nearly every patch. Minimum fix: normalize `\r\n`/`\r`→`\n` and strip a leading BOM in `_read` before the `old in current` test (and try UTF-16 when NULs appear). Residual fuzzy-only divergences (best-match picking a different occurrence, already-applied no-ops) remain an accepted approximation — worth a docstring line.

**P2-2 — the same substring test pulls in lookalike results from elsewhere in the draft (false block).** `matterkit/quotecheck.py:87-89`. The filter can't tell two occurrences of the same quoted words apart: draft line 1 already holds `He "never saw the warrant" Doc. 16 at 1.` (a pre-existing wrong page); an unrelated patch adds `She also says he "never saw the warrant" Doc. 16 at 2.` → the line-1 wrong-page result is kept (its quote ⊂ `new`) and blocks a clean edit. `test_old_problems_do_not_block_a_new_edit` only covers a quote-free `new`. The region-attribution fix above solves this too.

**P2-3 — V4A checks `+` lines only, so a quote whose cite sits on an unchanged context line reads as uncited.** `hermes_plugin/quote_guard.py:58-63`. V4A bodies keep unchanged lines as context; a patch inserting `+He "burned the warrant"` above an existing `Doc. 16 at 2.` citation-only line (which `_citation_only` folds into the unit, `briefcheck.py:1264-1268, 1276-1283`) gives a real file where the quote is checked against Doc. 16 → not found — but the guard sees only the `+` line → can't check → pass. Cheap improvement: include context (non-`+`/`-`) lines in the checked text and apply the same region attribution to keep results on the `+` lines.

**P3-1 — a pleading ¶-miss reports "wrong page" with an empty location.** `briefcheck.py:1642-1645` sets `q.status="wrong-page"` but never `q.where` → `describe` renders `wrong page: “…” (Compl. ¶ 59) is really at ` with a blank (`quotecheck.py:99-101`).

**P3-2 — several bad-cite findings never become Results, so they pass silently.** `quotecheck.py:83-85` maps only `pin-out-of-range`. A bare `Doc. 99 at 2` (doc not in store), a cite to a missing/changed source (`record-not-in-store`, `source-missing`, `source-changed`), `pin-unchecked` (page count unknown), and `paragraph-not-found` (`Compl. ¶ 99` absent) all emit no verdict — the write passes with nothing reported. Verdict-wise these are can't-check (pass) anyway, so it's messaging-only, but `Doc. 16 ¶ 9` isn't a RECORD_RE pin either, so a bogus `¶` number sails through unremarked — an asymmetry an agent could lean on.

**P3-3 — per-write cost.** `Docs.__init__` spawns `pdftotext -v` on every check (`briefcheck.py:718-723`); each cited doc is sha256-hashed twice (integrity at `:1495/1516` and again in `Docs.text` at `:775`); `suggest_docket` scans `documents` and two `authorities` scans run per write (`:1220-1222`); a cited PDF with no stored text runs `pdftotext` up to `timeout=120` (`:807`) inside the hook, re-extracted on every write since `Docs._cache` is per call. Bounded, but a no-text PDF can stall a tool call ~2 min and serial writes re-pay it. `MAX_CHARS` also silently skips drafts >2 MB (`quote_guard.py:39`) — undocumented in the README.

**P3-4 — a quotation spanning more than one page break is `found` regardless of pin.** `briefcheck.py:1663-1664`: `hit_pages == [0]` skips the pins test, so `"…" Doc. 16 at 1` for words spanning pp. 3–5 is exact. Inherited `/matter check` semantics — consistent under D4, but it is a real false pass worth knowing.

**P3-5 — quote binds to the first following cite, and cites inside quotations produce real findings.** `briefcheck.py:1609-1611`: `"X." Docs. 16 and 18.` checks X only against Doc. 16 → if it's really from 18 → not found → false block (inherited binding; `pin-ambiguous` warns about the pin side only). Also a record cite *inside* quoted text is still scanned — quoting a passage that itself mentions `Doc. 4 at 99` produces a `pin-out-of-range` Result and blocks the write even though the cite isn't the draft's own. Consistent with `/matter check`, but both stop an honest agent.

**P3-6 — path-scope leftovers.** Relative paths try `cwd` before `matter_dir` (`source_guard.py:96-108`): if the hook's cwd sits inside a different case, `Drafts/x.md` is checked against the wrong record → false block of an honest write (or a skipped check if cwd has no case). `.docx`/`.pdf` draft paths are unchecked by extension — `write_file("brief.docx", <text>)` bypasses both this guard and `draftdocs` (not a zip). Grok's open case/NFD findings on the shared `_candidates`/`_classify` matter less here than for the source guard: a classification miss makes the guard quote-check a registered source as if it were a draft — noise on a write the source guard owns, not a bad-quote path. `*** Move File:`/`Move to:` endpoints aren't parsed but moves carry no text; `*** Add File:` bodies are assumed `+`-prefixed — if Hermes's `patch_parser` accepts unprefixed Add bodies they're skipped (couldn't verify; `patch_parser` was outside the allowed read).

## Answers to points 1–8

1. **Verdict mapping.** Complete: `found|wrong-page|not-found|unchecked` → exact/wrong page/not found/can't check (`_STATUS`, `quotecheck.py:30`), `pin-out-of-range` → wrong page, and source-integrity failures → can't check with the BLOCK finding's message attached via `source_note` (`:69-73`). Checked the listed shapes: block/multi-paragraph quotes work under curly quotes (straight `"…"` is line-bound by `QUOTE_RE` — a multi-line straight quote is invisible to both checker and guard; inherited); page-break-spanning quotes count on both endpoint pages, multi-break always found (P3-4); `Id. at 3` binds the antecedent record cite incl. pin; pleading ¶ cites scope the quote to the cited paragraphs; `Docs. 16 and 18` pins the last doc and quote-binds the first (P3-5); nested single quotes aren't quotations at all (invisible — inherited); ellipses/`[brackets]` split fragments per `_fragments`; `text_copies` pages are preferred and hash-verified (`Docs._load:789-794`).
2. **False passes.** P1-1, P1-2, P2-1, P2-3 above are the reachable ones. Checked the named probes: `at 2–3` with words on p. 3 only is correctly exact (the range covers the page); a filename-suggested doc still gets quote-checked (it errs toward blocking, the safe direction); duplicate quote text keeps every occurrence's result (conservative, but P2-2). `Doc. 99 at 2` on an unregistered doc is can't check/pass per D1 — consistent.
3. **Patch handling.** See P1-2, P2-1, P2-3. `replace_all` semantics match (`str.replace` vs Hermes's flag) when the match is exact; non-unique `old_string` is a Hermes error the guard simulates as a first-occurrence replace — harmless since no write lands.
4. **Path scope.** Extensions and the `.matter`-ancestor rule are right (case-insensitive endswith, innermost case root, store/source skipped). Skipped-that-shouldn't-be and checked-that-shouldn't items are in P3-6; Grok's case/NFD findings don't change this guard's safety, just where its noise lands.
5. **Never raises / cost.** `on_tool_call` wraps each guard in its own try and `fallback` can't raise (`__init__.py:102-121`, `source_guard.py:66-83`); `check_text`'s failure modes (missing store, malformed docket, pdftotext timeout) all propagate into that catch → fail open, per D3. Cost in P3-3; the 120 s worst case is the only real stall risk.
6. **Messages.** Good enough to fix in one retry: verdict + quote + cite + real page/doc + the rewrite instruction. Absolute `root` is shown but it's the agent's own `matter_dir` — no leak beyond what it already sees. P3-1/P3-2 are the gaps.
7. **Ingest fix and test.** `from .store import new_id` is the right fix; no other absolute `matterkit` imports exist in `matterkit/` or `hermes_plugin/` (the `from agent.secret_scope` import intentionally targets Hermes's own package and ImportErrors to None). `test_plugin_package_imports.py` runs `python -I`, asserts the kit isn't on `sys.path`, loads the root package under a foreign name and drives `ingest_paths` — it really proves the fix.
8. **Gaps.** README "each quotation and record page cite in the new text is looked up" and plugin.yaml "refuse the write when a quotation is not in the document or is on a different page" are both broken by P1-1/P1-2/P2-1/P2-3. `terminal`/`execute_code` writes bypass quote checking entirely (consistent with the README's scope but worth a line there). Tests that would pass with the feature broken: every P1/P2 above — `test_v4a_added_lines_are_checked` passes `mode="patch"` yet the guard ignores `mode`, so it can't catch the dispatch bug; `test_only_keeps_results_from_the_new_text` exercises keep-behavior only for a whole-sentence `only`; nothing covers cite-only patches, sloppy V4A headers, CRLF/UTF-16 drafts, lookalike quotes, or cite-on-context-line V4A.
