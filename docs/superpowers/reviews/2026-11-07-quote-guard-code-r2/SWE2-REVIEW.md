## New breakage in the fix diff

**R2-1 (P2) — an `Id.` antecedent edit re-binds a following unit's results, which `regions` then drops — the P1-1 escape in cross-unit form.** `briefcheck._Checker` binds `Id.` to `self.last_target` — the last cite of the nearest preceding cited unit (`briefcheck.py:1450-1462, 1473-1475`). That state crosses unit boundaries; the region filter doesn't. Repro at `5fb9bc6`:

- Draft: `Smith testified. Doc. 16.\nHe "never saw the warrant" Id. at 2.\n` (both exact).
- `patch(old_string="Doc. 16", new_string="Doc. 18")` → `after` binds `Id.` to Doc. 18. The `Id.` unit now produces **two** blocking Results: `pin-out-of-range` (Doc. 18 is one page) and `not-found` for the quote — each carrying the *second* unit's span.
- The only region is the `Doc. 18` span inside unit 1 → unit 2's results are filtered → `problems == []` → the write lands `He "never saw the warrant" Id. at 2.` bound to a document that doesn't hold it.

Any retarget/delete of a full cite upstream of an `Id.` works the same way (`Id. at 9` re-binding to a short doc, `Id. ¶` pleading chains). This is routine input in this domain — `Id.` is the common legal citation form, and cite retargets are exactly the patches this guard exists for. Fix direction (pick one): when a touched unit contains or changes a record/pleading cite, also keep results from the following units that could bind it — i.e., keep through the end of the `Id.` chain (until the next unit with a full record/pleading cite); or diff the verdicts on `current` vs `after` and keep results that are new or worsened. `quote_guard.py:82-84` + `quotecheck.py:109-110`.
