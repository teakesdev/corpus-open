## New breakage in the fix diff — all P3, none blocking

**N1 — `_sentence_spans` also suppresses the boundary at a quote's closing `.` (`briefcheck.py:326`).** The guard tests only the punctuation's offset (`a < cut < b - 1`), so the `.` immediately before a closing `"` counts as "inside" and the split after `." ` never happens: `He wrote "Denied." She appealed.` becomes one unit. Harm: an uncited factual sentence directly after a quote-ending sentence escapes `uncited-fact` when the merged unit gains a cite — `STATEMENT OF FACTS / He filed it "late." She knew. Doc. 16.` → quote checked, clean row, `She knew.` unflagged (pre-fix it was flagged). With no cite the unit still surfaces via `quote-uncited` UNCHECKED, so the failure needs fact-section + quote + a cite — narrow. A tighter test would require the whole match (`.…\s+`) inside the span, e.g. `a < cut and start + m.end() <= b`.

**N2 — `[\w']{0,6}` allows tail-matches the alteration didn't intend (`:519`).** `[w]ord` compiles to `[\w']{0,6}ord` and also matches "sword"/"password"; `[A]nd` matches "end"/"band". The contract is disclosed in the docstring ("frees only the bracketed part") and every non-altered word is exact, so a false `found` needs all surviving fragments to match in order — real but bounded. `{0,2}` or capping by bracket length would tighten it; not required.

**N3 — `_pdf_page_count` residual edge cases (`:468-488`).** (a) A `/Pages` node containing a nested dict (legal: inheritable `/Resources <<…>>` on an interior node) fails `_PAGES_NODE` → if that's the root, the count falls to the largest interior `/Count` → under-count → false `pin-out-of-range` (fail-safe direction: blocks rather than passes). (b) `stream\r` line endings and stream data containing the bytes `endstream` leave small scan windows in `_strip_streams`. Both are narrow; the fix's direction (never trust content streams) is right.

**N4 — `LOCAL_WORDS_RE` reads every flavor as `local_rule` (`:128-130`,`:258-262`).** "Local Criminal Rule 16" / "Local Bankruptcy Rule 5001" key to `rule:lucivr16`/`…5001` — mislabeled but disclosed by the `(read as L.U.Civ.R. N)` display, same convention as bare `Rule 15`. Also under-matches: `Local Civil Rules 7 and 15` yields only `7` — the `RULE_TAIL_RE` continuation exists only on the abbreviated forms, so `and 15` is silently unmatched. A tail loop after `LOCAL_WORDS_RE` would close it.

**N5 — doc nit:** the module docstring's docket-map example (`:16-21`) omits `local_rule` and `operative_pleading`, both now honored keys.

## Handoff points 1–5

1. **`_fragments` false-found.** A word-spanning bracket (`[the officer]`) and any bracket containing whitespace split the quote — can't become a word pattern. Apostrophes are fine (`[\w']` on both sides). A quote of only brackets/ellipses yields zero fragments → `quotes()` skips it entirely (`:1044`) — no false found, though it is silently dropped (pre-existing, unchanged). The residual is N2's wildcard tail-match.
2. **Unpaired straight `"`.** `QUOTE_RE`'s straight branch requires a closing `"` before a newline (`[^\"\n]`,`:144`) — an unpaired mark produces no span, so the no-split rule can't see it and nothing is suppressed. Paired stray marks (e.g. inch pairs `5" … 4"`) still form a "quote" — pre-existing — and now suppress interior cuts; the unit still surfaces via `quote-uncited`. The real harm case is N1 (paired quote ending a sentence glues the next one on). Curly pairs legitimately span newlines within a block — that's the intended case.
3. **Page-break pairs.** `range(len(pages)-1)` covers the last pair; single-page docs and quotes fully on p1/pN never reach it. `pins` empty → `found` labeled `pp. p–p+1`; several pins → `any(lo<=x<=hi for x in (p,p+1) …)` checks each range against both pages — correct. Residual: quotes spanning ≥3 pages still land on `hit_pages=[0]` → `found`/"across a page break" with pins unverified (`:1094-1105`).
4. **`LOCAL_WORDS_RE` over-match.** `"local rules require"` (no digit) can't match — `Rules?\s+\d` is required. "Local Rule" inside a name (`Local Rule Co.`) — no digit follows → no match. The over-match that exists is N4: non-Civil flavors are read under `local_rule` — disclosed, not silent.
5. **`load_docket` vs documented maps.** No. The documented flow (`docket suggest > .matter/docket.json`) emits `{"entries": {…}, "ambiguous"?: {…}}`: entry keys are `\d{1,4}(-\d{1,3})?` by construction and `ambiguous` is an unvalidated extra key, so it round-trips. `text_copies`/`pleadings` are str→str as documented. Only non-dict maps, bad entry keys, or wrong value types are refused — and `--docket` alt maps get the same validation.
