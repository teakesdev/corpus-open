## Findings

### P1

**F1. `lit:` lines with leading whitespace silently become wrong literals** — `scripts/leak_scan.py:128`
`text.startswith("lit:")` is tested on the stripped line, but the slice `raw.rstrip()[len("lit:"):]` runs on the *unstripped* `raw`. Input `"  lit:zebra"` compiles `t:zebra`; the operator sees `2 case pattern(s) loaded` and has no way to notice a dead pattern. Same defect class: a `LIT:` prefix or a UTF-8 BOM on line 1 (`\ufefflit:x`) falls through to the regex path and compiles to a literal that never matches the identifier. For the one class that cannot be silenced and whose output reveals nothing, this is the worst kind of failure. Trigger: any patterns file with indented or BOM'd `lit:` lines. **[required]** Fix: `source = re.escape(text[len("lit:"):])` (slice `text`, not `raw`), tolerate BOM via `utf-8-sig`, add a test with an indented `lit:` line.

### P2

**F2. Pushing to a URL scans (and can block on) all local history** — `scripts/pre-push.sample:20,34`
git hands `$1` the URL when no named remote is used (`git push https://… main`). `--remotes=<URL>` matches no ref, so `--not --remotes=<URL>` excludes nothing and `git log` walks every commit reachable from `local_sha`. On any repo whose history still carries a finding, a clean push is blocked — the exact outcome that trains users to pass `--no-verify` or uninstall the hook. **[required]** Fix: `git remote get-url "$remote" >/dev/null 2>&1 || remote=''` and fall back to `--not --remotes` (all tracking refs) when the name isn't configured; add a URL-remote hook test.

**F3. `diff --git` path extraction breaks on C-quoted names and on `diff.noprefix`/`srcPrefix` config** — `scripts/leak_scan.py:346-355`
`-c core.quotepath=false` only disables high-bit quoting; names containing `\t`, `"`, `\` or `\n` still print as `"a/x\ty" "b/x\ty"`. `rest.startswith("a/")` fails and `split(" b/",1)` finds nothing, so `path` becomes the whole quoted pair: name checks (transcript `.jsonl$` anchoring, case-pattern path match) silently skip and `where` prints garbage (content lines still scan, so it's a name-check + location defect, not a content miss). The same misparse happens for users whose gitconfig sets `diff.noprefix`, `diff.srcPrefix`/`dstPrefix` or `diff.mnemonicPrefix` — headers arrive as `diff --git x y` or `i/x w/x` and the half-split silently yields garbage. Tests run with `GIT_CONFIG_GLOBAL=/dev/null` so they can't see this. **[required]** Fix: force `-c diff.noprefix=false -c diff.srcPrefix=a/ -c diff.dstPrefix=b/` in the `git log -p` call, and parse the `+++ b/<path>` header line (or C-unquote) instead of bisecting the `diff --git` line.

**F4. `scan_tree` unguarded `open()` → traceback that prints the raw path** — `scripts/leak_scan.py:264-265`
A file that is unreadable or disappears between `ls-files` and `open` raises `PermissionError`/`FileNotFoundError`, uncaught. The traceback writes the absolute path (which may contain a case identifier, or `/Users/ty` when scanning outside a repo) plus the script's own absolute path to stderr — a `where`-bypassing leak, exit 1 rather than 2. **[required]** Fix: wrap the open/read in `try/except OSError` → `ConfigError` (exit 2, sanitized message) or a `notes`-entry skip. <!-- leak-scan: allow -->

**F5. File names are never checked for home-path or email, and `where` is never redacted** — `scripts/leak_scan.py:188-198, 105-112`
`scan_path_name` only runs `TRANSCRIPT_NAME_RES` and case patterns over names. A committed `jane.doe@gmail.com-notes.md` produces no finding, and because `where` is emitted verbatim even under `--redact`, the address lands in the public CI log anyway. Trigger: any file whose name embeds an address or `/Users/x`-shaped component. **[required]** Fix: run `EMAIL_RE`/`HOME_RE` over the basename in `scan_path_name` (respecting `--allow-email`), so a leaking name is at least a finding; consider masking suspicious components in `where` too. <!-- leak-scan: allow -->

**F6. `.jsonl$` in `TRANSCRIPT_NAME_RES` flags every JSONL file** — `scripts/leak_scan.py:82`
Any `data/train.jsonl` or `evals/cases.jsonl` (this repo has an `evals/` dir; none today) reds CI — the classic "step gets turned off" FP. Same mechanism FPs on product files like `chat-export.py` or `session-history.md` (`chat`/`session`/`agent` are agent words). **[required]** Fix: require an agent-word or session-marker shape for `.jsonl` (e.g. `(_AGENTS).jsonl$`), or keep `.jsonl$` but document `--exclude`; also make the CI step pass an `--exclude`/`--allow-email` config so legit public addresses/names don't red the build with no knob.

**F7. `push` to `main` never range-scans; `--check-authors` is wired to nothing** — `.github/workflows/ci.yml:41-48`, `scripts/leak_scan.py:401`
The range step is gated on `pull_request`, so a direct push to `main` gets only the tree scan — commit-message and author/committer email leaks sail through (and the founder's own evidence shows every commit carries a personal author address). Compounded by fork PRs, where `secrets.` is empty so `pattern #N` checking silently skips: a fork PR introducing a case identifier merges green and is only caught — post-publication — by the `push` tree scan. **[required]** Fix: add a range step for `push` over `${{ github.event.before }}..${{ github.event.sha }}` (guard `before == 0{40}`), pass `--check-authors` there (and in `pre-push.sample`), and accept that fork PRs can't check case ids — document it or add a `pull_request_target`-style gate.

**F8. Ref names are never scanned** — `scripts/pre-push.sample:26-38`
Pushing `refs/heads/<case-slug>` or a tag publishes the identifier; the hook only scans commits. Fix: run the pattern set (and transcript name regexes) over `$local_ref`/`$remote_ref` — a cheap `scan_path_name`-equivalent pass.

**F9. `ConfigError` echoes the patterns-file path** — `scripts/leak_scan.py:120`
`--patterns ~/cases/<name>/p.txt` on a missing file prints the full private path to stderr. Mask it (`mask_path`-style or basename only).

1. **Detection.** The allowlists are well-judged (reserved domains, noreply, `git@` hosts, file-TLDs) and verified FP-free against the actual tree today. Over-flagging risks: `.jsonl` names (F6), agent-word+`export/history/conversation` filenames, `user@service-host` addresses, selectors whose id matches the user-email marker, service-user homes — F6/F12/F16. <!-- leak-scan: allow -->
2. **Case patterns.** The `#N`-only discipline holds through `scan_line`, `mask_path`, notes, and JSON/text output — every `where` is masked. Holes: `ConfigError` prints the patterns-file path (F9); uncaught `OSError`/`ValueError` tracebacks print raw file paths (F4); `_git` echoes git's stderr tail which can contain a caller-supplied remote/rev (F14); a case identifier riding inside a *different* class's `detail` (e.g. `jane@<case-name>-law.com` as an email finding) prints when `--redact` is off (CI is safe; local output isn't). `load_patterns`: the empty-match guard works (`regex.search("")`), but F1's slicing bug is confirmed — and it makes the *count* right while the pattern is wrong.
3. **Range scanning.** The `--cc` state machine is correct: `parents` column width from `@{2,}`, added/context lines advance `new_line`, `-`-only lines don't, `finish_file` covers hunk-less entries (binary, mode-only, empty new files), `deleted`/`named`/`skip_file` reset properly, `--no-renames` forces delete+create so nothing hides in renames, merge resolutions scan (test-proven). Slips: F3's name-parse failures (quoted names, `diff.noprefix` family). Line numbers come out right for normal and combined hunks. `check_authors` correctly dedupes author/committer and honors `--allow-email`.

UTF-16 BOM handled; UTF-16 *without* BOM hits the NUL check and is skipped silently. `cat-file --batch` parsing is correct; its `stream.index`/`int()` failures are uncaught (traceback, exit 1) — same class as F4.
5. **Fail-closed.** 0/1/2 all correct: missing/invalid patterns file, empty spec, bad range, missing git, non-dir `--tree` → ConfigError → 2. Broken: URL remote (F2). Missing: ref-name scan (F8), `--check-authors`, `</dev/null`. Never run as a real hook — disclosed, acceptable for a sample.
