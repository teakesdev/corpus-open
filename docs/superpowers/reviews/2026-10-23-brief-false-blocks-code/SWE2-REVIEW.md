## Answers to the five points

1. **Rule binding (most important).** Sound. `at = u.start + a` gives absolute draft offsets; the `r[0] < at` filter is what enforces "earlier" (C2's claim verified — `RULE_RE` yields before `BARE_RULE_RE` within a unit regardless of position, so yield order alone could not do it). `max(earlier)` = most recent by offset; `at` is unique per cite (distinct match starts), so no tie risk. Binding only retargets to a cite the writer wrote, and every bind is disclosed (`read as <prefix> <rest>, after the full cite on line N`). `5.1`/`5.10`/`51` are distinct `num` keys — no merge at the binding layer (the `5.1`→`51` collision in `_norm_key` is pre-existing key-space behavior, unchanged). Rule-list tails register as binding targets per C1; `Id.` after a bound bare rule takes the bound target — consistent. **C1 endorsed**: a bare `Rule N` is formally the `bare_rule` family, and binding it to a logged local rule would let an unlogged FRCP N pass — the current behavior forces disambiguation and the display shows why. **C2 endorsed** as implemented.

2. **`_ANNOTATED` / `_ANNOTATED_HEAD`.** `_ANNOTATED` is safe: `Ann`/`Annotated` is only ever the annotation marker in legal citation (the `\b`/`.`/`otated` alternatives reject `Annual` etc.), and it cannot merge two *different* statutes — only editions of the same one, which is D2's intent. `_ANNOTATED_HEAD` cannot cross a sentence within the search region (`$` anchors at endpos or before a newline at `a-1`, so the head must abut the `§`) and cannot claim another cite's span (the absorbed text is word-fragments, and `free()` runs after extension — overlap would only drop the cite). It *can* absorb a preceding abbreviation — P2-1. `authority.find`/duplicates: loud, acceptable — P3-2. `search(s, 0, a)` runs on one unit (a sentence) — no cost concern.

3. **`citations.py`.** `(?:-\d+[A-Za-z]?)*` is safe against claim/overlap rules — it's a single ordered pattern; its larger claims can't shadow the `§` patterns (different text); the trailing-period strip still applies; the xref member split produces the documented nested rows. Holdout behavior unchanged given the eval evidence (the only differing inputs are absent from the corpus). C4 acceptable with P3-3's caveat. C5 not worth fixing now — P3-5.
