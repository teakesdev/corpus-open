## Findings

### P1 — `Id.` binds to the wrong cite whenever cite kinds interleave in one unit

`matterkit/briefcheck.py:828-829` — `prev = [x for x in cites if x.start < m.start()]; base = prev[-1]`.

`cites` is appended in *pattern-bucket order* — all `RECORD_RE` hits (:795), then `PLEADING_RE` (:805), then `_scan_authorities` yields pattern-by-pattern (:816). The `cites.sort(key=start)` at :846 runs *after* the `ID_RE` loop, so `prev[-1]` is the last cite in list order, not the nearest preceding cite in text order. Worse, `_citation_only` folding means "Doc. 16 at 2. Id. at 3." lands in the same unit as a preceding case cite, so this is not an edge case — "case cite. record cite. Id." is an extremely common brief pattern.

**Scenario:** store has `Dietz v. Bouldin, 579 U.S. 40 (2016)` (source-checked, pins `45-47`) and a 2-page `Doc. 16`. Draft: `"Defendants moved. Dietz v. Bouldin, 579 U.S. 40 (2016). Doc. 16 at 2. Id. at 99."` → cites list = `[record@30, case@0]` → `prev[-1]` = the case → `Id. at 99` is judged against the case's pins (spurious `pin-not-in-check` WARN) while Doc. 16's pin `99` — which should be `pin-out-of-range` BLOCK on a 2-page doc — is never checked. Reversed statuses give false BLOCKs: if the case were unverified, a legitimate `Id. at 2` on Doc. 16 reports `authority-unverified`.

**Fix:** `base = max(prev, key=lambda c: c.start)`, or move the `cites.sort` above the `ID_RE` loop (Id cites appended during the loop have increasing `start`, so ordering stays correct for chained `Id. Id.`).

### P2 — `_fragments` drops the post-bracket part of every altered word

`matterkit/briefcheck.py:480` — `re.split(r"\w*\[[^\]]*\]\w*|...", quote)` removes the *entire* token containing brackets, so `[M]otion`, `[C]ourt`, `obje[c]ts` leave no fragment to verify. Case-alterations are ubiquitous in real quotations; each one silently drops a word.

**Scenario:** source text is `"the ruling was denied"`; draft quotes `the "[M]otion was denied." Doc. 1 at 1.` → fragments `["the"],["was denied"]` → both found → quote reported **found** although "Motion" never appears in the source.

**Fix:** reconstruct altered words before splitting — `re.sub(r"\w*\[([^\]]*)\](\w*)", r"\1\2", quote)` — so `[M]otion`→`Motion`; remaining bare `[...]` (true substitutions) still split out. Same helper is reused by `authority.check`'s artifact-quote gate (`authority.py:106`), so the hole exists there too.

### P2 — "not tied to a source" findings are WARN, so exit 0 still claims `ALL TIED TO SOURCES`

`matterkit/briefcheck.py:855` (`uncited-fact`), `:963` (`quote-uncited`), aggregated at `:583-591`.

D1's contract: exit 0 means *every* item is tied to a source in the store; exit 2 is for "items only a person can check." A Facts-section sentence with no cite, or a quotation with no cite in the sentence, is definitionally untied and checkable only by a person — the exit-2 class. Today a draft consisting entirely of unattributed quotes exits 0 and `summary()` prints `ALL TIED TO SOURCES` — the headline claim contradicts the findings table beneath it.

**Scenario:** Facts section with `"Plaintiff was home."` (no cite) → `uncited-fact` WARN → `check()` returns exit 0 / `ALL TIED TO SOURCES`. **Fix:** reclassify `uncited-fact` and `quote-uncited` as UNCHECKED (they match the exit-2 definition), or make the state-0 label not assert all-tied when warnings exist.
