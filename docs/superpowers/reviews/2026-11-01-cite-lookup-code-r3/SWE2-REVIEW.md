## 2. New breakage in this range

### P3-1 — spelled-out suffixes and common party words still yield false FOUND
`citelookup.py:153-155` (`_STOP`), `197-218` (`_GENERIC`), `280-283`. `_STOP`/`_SUFFIX` cover only abbreviated corporate suffixes (`inc`, `ltd`, `corp`, `co`); spelled-out `Limited` and `Incorporated` are treated as ordinary *distinctive* words, as are common party words missing from `_GENERIC`: `trading`, `investment(s)`, `ventures`, `electronics`, `scientific`, `aviation`, `automotive`, `machinery` (stem `machin` is len 5, below the 7-char `_LONG_STEMS` cut), `mining`, `steel`, `guaranty` (stem is `guarant` — spelled-out Guaranty diverges), `builders`, `logistics`, `consulting`, `leasing`.

Synthetic: draft `Alpha Limited v. Doe, 1 F.3d 1` where CourtListener holds `Beta Limited v. Roe` at that cite → `distinct = {alpha, limited}` (`doe` generic) ∩ `{beta, limited, roe}` = `{limited}` → **FOUND** — a different case passes the name check. Same for `Smith Trading Co. v. Doe` vs `Jones Trading Ltd. v. Roe` (`ltd` stopped → `trading` is the only shared distinctive). Reachable via `_case_name` (capitalized words kept). Bounded — the shared distinctive must be exactly a missed generic and the cite genuinely mis-pointed — but it is precisely the unsafe-direction class `bb9ba9f` set out to close, and the handoff asked for exactly this sweep. Fix: move spelled-out suffixes (`limited`, `incorporated`, `llc` variants) into `_STOP`/`_SUFFIX` handling and add the industry words to `_GENERIC`.

### P3-2 — `cite extract --status` still silently ignored; spec §9 overstates
`matter.py:481-490`. `--status` is a *list* flag; `extract` accepts and ignores it — the same silently-doing-nothing behavior the finding targeted, on the mirror-image side. Spec §9's row now claims "each `cite` subcommand refuses flags that are not its own", which the code does not deliver. Also `--max-requests 0` slips through `value not in (None, False)` because `0 == False`. Synthetic: `matter.py cite extract case draft.md --status extracted` → exit 0, flag ignored. Fix: extend the refusal to `--status` on extract (and `not in (None,)` vs. explicit `is not None and value is not False` if `0` should also be refused).

### P3-3 — a skipped record write does not force exit 2
`matter.py:567` counts only actions starting `"not written"`; `citelookup.py:474-476` emits `"several store rows answer to this cite; nothing written"` for an ambiguous store match — a FOUND cite a human must resolve, yet the run can exit 0 with no stderr hint.
